# 方法说明

## 目标

用有限现金撑过一段到账日期不确定的时期，并在助学贷款到账后转为一年生活费计划。界面中的每个数字都必须能解释、能追溯，不能制造“还有很多钱”的错觉。

## 核心公式

- 安全缓冲 = 已到账金额 × 20%
- 可安排现金 = 手头现金 − 安全缓冲 − 未支付的大额计划
- 每日总上限 = 可安排现金 ÷ 距离预计到账日的剩余天数（包含今天）
- 今日还能花 = 今日总上限 − 今天已经花掉的钱，最低为 0
- 账户余额 = 该账户到账 − 该账户消费 − 转出 + 转入

金额一律用整数“分”存储，避免 `0.1 + 0.2` 类浮点误差。

## 原理与界面动作

| 原理 | 界面动作 |
|---|---|
| 不确定的到账日应按最晚日期规划 | 首页同时展示 11/30、12/15、12/31 三种每日上限，默认采用 12/31 |
| 总额不多时，安全缓冲必须和日常额度分开 | 20% 缓冲独立展示；动用需要二次确认并记录 |
| 总体有钱不等于能洗衣服 | 微信、支付宝分开显示；洗衣和吹风快捷按钮强制选择支付宝 |
| 账户互转不是消费 | 互转单列，不改变总生活费；余额按转出、转入重算 |
| 预付课程是现金先减少，上课不是再次消费 | 900 元课程包付款时扣一次现金，之后只减少剩余次数 |
| 未支付的大额支出不能被摊薄成每日可花金额 | 计划支出先从可安排现金中扣除，付款后再转为消费 |
| 隐私和离线优先 | IndexedDB 本地保存、JSON 备份、Service Worker 离线壳 |

## 功能红线

1. 不允许把 20% 安全缓冲自动计入每日可花额度。
2. 不允许把微信余额自动算进支付宝可用余额。
3. 洗衣机和吹风机快捷记录不得默认使用微信。
4. 未知到账日期不得默认按较早日期计算每日额度。
5. 课程包上课只能在付款后减少次数，不能重复扣现金。
6. 没有用户确认不得覆盖本机账本。
